# 公共分析数据：向量、误差与可用状态

## 属性是计算数据，不是向量画面

分析节点用帧属性携带几何、向量和误差。可见画面的尺寸或格式不自动决定这些数据的意义。其他生产者也可以生成合法数据；消费者不依赖原始节点身份。

属性名是 `prefix` 直接连接后缀，默认例如 `MVUtensilsAnalysisPel`。所有标量均为宿主 int64 元素；向量和误差也是 int64 数组，不是序列化的原生结构体。

## 描述信息

| `Analysis` 后的后缀 | 含义 |
| --- | --- |
| `Width,Height` | 不含 padding 的工作尺寸，正且不小于实际尺寸 |
| `RealWidth,RealHeight` | 实际图像尺寸，正 |
| `HPad,VPad` | 每侧亮度 padding，非负 |
| `Pel` | 每像素向量单位，1、2、4 |
| `Levels` | 分析使用层数，至少 1；不表示导出多层数组 |
| `Chroma` | 色度是否参与误差，零/非零 |
| `XRatioUV,YRatioUV` | 每轴 1 或 2；GRAY 为 1、1 |
| `BlkSizeX,BlkSizeY` | 块尺寸，各至少 2，具体函数另有限制 |
| `OverlapX,OverlapY` | 每轴 0 到半块 |
| `NBlkX,NBlkY` | 网格尺寸，正 |
| `DeltaFrame` | 参考帧 `n+d` 的 d；公共格式允许 0，Analyse 自身不生成 0 |
| `BitsPerSample` | 整数 8～16，或浮点分析 32 |

读取标量元素 0，缺失、空或类型不对都先得到零，后续元素忽略；除 `Chroma` 使用完整 int64 零/非零外，先饱和到 int32 再验证范围。因此缺少 `Chroma` 可得到合法 false，缺少 `Pel` 得到非法 0。

## 数组怎样解码

`AnalysisSAD` 保存所选亮度度量（SAD、SATD、DCT 或混合度量）的误差，启用色度时再加色度 SAD。描述字段中没有度量标识。消费者直接用这些误差计算阈值、权重和蒙版，不重新计算像素 SAD，也不把误差换算为统一度量。Recalculate 则独立选择度量重新测量。

总数 `N=NBlkX·NBlkY`，行序索引 `i=by·NBlkX+bx`。`AnalysisVectors` 的低 32 位为有符号 X，高 32 位为有符号 Y；`AnalysisSAD` 为非负原始误差。打包和采样单位详见 [Analyse](../analyse.md)。

每块带 padding 起点 `x0=hp+bx(Bx-Ox),y0=vp+by(By-Oy)`，公共向量必须满足：

$$-px_0\le v_x<p(W+2h_p-x_0-B_x),\quad
-py_0\le v_y<p(H+2v_p-y_0-B_y).$$

上界不包含。这个公共范围验证不代替具体渲染器对其采样脚印的检查。

## 原始误差与用户阈值单位

搜索比较代价可以包含预测距离和候选惩罚；`AnalysisSAD` 保存最终候选新测得的原始误差，不含这些惩罚。Recalculate 即使未达到搜索门限也会重新测量，不复制旧误差，也不继承生产者的度量选择。

整数 SAD 对面积 A、恒定差值 d 的贡献为 A·d，单位是输入的原生像素码值，不自动按位深除回 8 位。启用色度时，按两个色度块实际的下采样尺寸分别求 SAD 后相加。因此 8×8 块各平面均相差 1 时，GRAY 为 64、YUV420 为 96、YUV422 为 128、YUV444 为 192。8、10、16 位中相差一个码值的这些结果相同；相同归一化亮度变化在高位深中需要更大的码值差。

整数 SATD 对每个 4×4 Hadamard 单元求系数绝对值和后除以 2。8×8 亮度块恒定相差 1 得到 32；只有一个像素相差 1 时，SAD=1、SATD=8。色度仍使用像素 SAD。float SAD/SATD 则先对每个完整平面的误差按 65535 尺度编码，再加各平面整数结果；详细舍入、饱和与非有限值规则见 [Analyse](../analyse.md) 的浮点误差说明。

以下 GRAY8、8×8 精确例子区分各度量：

| 恒定源/参考值 | SAD | SATD | DCT（DC 权重 4） | local SAD/DCT（DC 权重 1） | local SAD/SATD |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 / 1 | 64 | 32 | 0 | 32 | 48 |
| 0 / 4 | 256 | 128 | 32 | 132 | 192 |

local 例子均使用 weight=0.5、threshold=0。DCT 对各块独立量化，DC 使用整数 `sum/(2A)`，所以 0 与 1 的量化 DC 相同。只有一层时，global Analyse 使用 SAD；在 0/4 例子中，Recalculate 的固定全局权重分别产生 SAD/DCT=144、SAD/SATD=192、half-global SATD=224。度量名称或更低的原始误差均不能单独证明运动估计更好。

对 Compensate/Degrain 的 `thsad` 和场景判断的 `thscd1`，令 A 为亮度块面积；分析未启用色度时 C=1，否则 `C=1+2/(rx·ry)`；`D=(2^min(bits,16)-1)/255`。非负用户阈值 t 换算为：

```text
T = floor(t · (A/64) · C · D + 0.5)
```

位深和色度来自分析描述字段，即使渲染剪辑使用另一精度，也不改变此来源。GRAY 8×8 的 t=400 在 8 位时得到 T=400，10 位时为 1605，float 分析时为 102800。这是在换算用户阈值的单位，不是把 SATD、DCT 或混合误差转换为 SAD。

Recalculate 保留不同的舍入顺序：先对位深执行 `trunc(t·D+0.5)`，再乘 A、除 64 并截断；若启用色度，再加 `2·trunc(T/(rx·ry))`。10 位 YUV420、4×4、t=1 时，其阈值为 1，而渲染/场景阈值为 2。不能把这两套公式作为普通算术整理合并。

| 消费者或判断 | 误差 E 恰好等于阈值 T 时 |
| --- | --- |
| Compensate 块选择 | 使用当前块；参考块要求 E<T |
| Degrain 可靠性 | 为零；参考仅在低于 T 时有贡献 |
| 场景坏块计数，Flow 也使用此判定 | 不算坏块；坏块要求 E>T |
| Recalculate 细化 | 保留映射向量和新测误差；搜索要求 E>T |

判为场景切换还要求坏块总数严格大于百分比换算后的数量阈值。这些相等边界与所选度量无关。

## 三种状态与损坏数据

1. 标量有效值不在合法域内，得到 **InvalidMetadata**，不读数组。
2. 元数据有效，但任意数组缺失或长度不等于 N，得到 **MetadataOnly**。先比长度，不先检查数组类型和元素。
3. 两个长度都正确，才验证都是整数数组、SAD 非负及向量范围。全部通过才是 **Complete**；此时损坏元素报错，不降级为缺失数据。

只读元数据的操作在标量检查后就停止，不认证数组。完整的零向量、零误差是有效测量，不能与没有数组混淆。

例如 N=4 时，向量长度 4、误差长度 3 得到 MetadataOnly，即使短数组是浮点类型；两个长度都为 4 而误差为浮点类型则报错。

## 场景判定怎样参与参考可用性

[SCDetection](../sc-detection.md) 解释按面积、色度、位深换算误差阈值，再统计坏块数量的计算。许多图像消费者复用这套判定：元数据无效、数组缺失或场景变化可以让参考不可用，完整但损坏的数据仍是错误。

不同函数对不可用状态的反应不同：Analyse 在参考越界时不生成数组；Recalculate 可把缺失旧数组当零向量后重新测量；渲染函数可能回退到中心图像。必须在函数自己的计算规则中确定，不能由公共解码器统一填零。
